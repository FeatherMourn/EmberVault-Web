# EmberVault Web Roadmap

## Purpose

Publish reviewed, sanitized EmberVault catalog records, research summaries,
compatibility data, and community-created content.

## Scope

Included: public schemas, validation, publication review, static catalog
rendering, sanitized imports, blueprint sharing, and upload intake.

Excluded: private profiles, save data, credentials, direct desktop control,
automatic installation, and execution of uploaded content.

## Milestones

1. Align public schemas with shared Contracts.
2. Validate incoming sanitized snapshots and preserve capability states.
3. Add reviewed project and research publication workflows.
4. Add a community blueprint and content library with previews, tags,
   authorship, licenses, compatibility, evidence state, and version history.
5. Add upload intake for blueprints, editable projects, preview images,
   evidence attachments, and generated package metadata.
6. Quarantine and validate uploads for file type, size, unsafe paths, malware,
   required metadata, hashes, and supported schema versions.
7. Require authorship and license declarations and label content as verified,
   experimental, research-only, blocked, or unsupported.
8. Add review queues, rejection reasons, resubmission, moderation history, and
   explicit publication approval.
9. Publish approved content as downloads or handoff packages only; never
   execute uploaded code, install mods, or mutate a user's game.
10. Add search, categories, tags, favorites, compatibility filters, and
    separate blueprint, fixture, export, and evidence views.
11. Verify static deployment, privacy boundaries, and clean publication builds.

## Definition of done

- [ ] Public snapshots contain no private workspace data.
- [ ] Incoming records and uploads are schema-validated and hashed.
- [ ] Upload intake scans and quarantines content without executing it.
- [ ] Publication preserves authorship, license, provenance, compatibility,
      evidence state, and moderation history.
- [ ] Approved downloads are separate from private evidence and runtime
      operations.
- [ ] Site verification and deployment checks pass.
- [ ] Changes are committed and pushed.
